# Selected Source Proposal Collection

FT-IMP-161 provides an **opt-in in-memory integration**, not a running weekly scraper, LLM service or public refresh. It reuses the bounded collector and exact selected-source guard. This run uses synthetic HTML, fake transport responses and disposable checkpoint journals only; no actual source is requested again. Original155-160 packets, native journals, public facts and weekly baseline/due dates are unchanged.

`createProposalCollector` takes a reviewed plan, selection, access-hold registry, field registry, processing scope, explicit `collect:true` and a trusted synchronous local `propose` function. Processing scope pins the plan, selection, holds and complete field registry, then limits exact official sources and pilot fields. The scope is **operator-supplied review evidence**, not an automated robots/terms/license evaluator or an access authorization. Before live use the operator must independently document source-specific access and transient-processing permission. No live-approved processing scope is created in this transaction. An allowlist or a matching hash is not permission.

Use `collector.executeSource` only as the registered checkpoint's `executeSource` callback. The checkpoint passes its exact source index, plan hash and immutable attempt timestamp as a second argument; legacy callbacks that ignore that argument are unchanged. The adapter validates and copies that context before starting a request. Its per-instance latch refuses a second execution of the same source. The durable checkpoint remains the authority for no-replay across instances/processes; passing a context-shaped object alone does not authenticate a durable journal.

The selected executor permits one exact-address request, never a redirect recovery. The collector invokes its optional observer only after eligible HTML passes existing HTTP/type/size/challenge checks. Normalized text and hash go directly to the trusted local proposer in memory. The proposer must return untrusted structured proposals synchronously with exact source/hash/field/span joins; it cannot approve a fact, accepted party, source date or publication. Async-function proposers are rejected before collection, and returned promises are rejected without awaiting. This is not a sandbox for malicious callbacks or a model plugin: trusted local code still runs with the process's privileges and can block. No network-capable/model proposer is authorized here.

The typed boundary from160 keeps every admitted row and context pending. The integration returns the ordinary compatible source outcome to the checkpoint and separately exposes a body-free `reviewPackets()` copy. A malformed/unsupported/throwing proposer yields `rejected-proposals-review` without copying exception text or destroying a known HTTP/text outcome. A failed, blank/challenged, unsupported, oversized or redirected source yields `source-not-retrieved-review`; neither state authorizes retry. Underlying optional observer failures also do not turn known retrieval into an unknown network result. The default collector, audit CLI and weekly scheduler never enable this hook automatically.

Packets carry plan/selection/hold/field-scope pins, URL/index, exact checkpoint attempt time, outcome/status and text hash. `same-in-process-fetch-text` means the proposal boundary consumed the text hashed by this invocation; it is not independent remote authenticity, semantic validity or policy reconciliation. Injected test transport is explicitly synthetic. No supporting quote or full body is returned or persisted by the adapter. This does not enforce retention against a malicious trusted callback; permitted local processing remains operator responsibility.

The proposal queue is currently **memory-only**, not a durable journal extension. The registered owner must retain the body-free packet as an immutable reviewed output after collection. If a process exits before that handoff, a completed source outcome does not prove the proposal packet exists. Hold that source's proposal review as missing; do not replay a completed request, fabricate a packet or call the weekly handoff complete. Durable sidecar publication/coverage reconciliation is the next integration gate. A crash after starting but before a valid collection result remains the existing unknown-outcome owner hold.
