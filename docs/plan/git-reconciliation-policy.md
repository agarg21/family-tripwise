This is a standing exception to older unattended-merge language in repository and heartbeat instructions. ## Operating Gates

Fetch and pin local HEAD, remote main, common ancestor and complete outgoing range. Inspect incoming paths against dirty paths. Preserve all existing commits and every nonowned dirty byte/mode. Use a normal merge; keep the merge uncommitted until its index, full composed tree and ownership are inspected. Never use an automatic stash, rebase, reset, forced checkout, discard or force-push as a shortcut.

Run focused and full native QA on the clean release candidate, not a tree containing unreviewed dirty overlays. Require a different independent read-only PASS or PASS_WITH_P3. Exact-path staging, source/human/privacy gates and any applicable production validation still apply. A deterministic evidence-backed conflict outcome may be handled under this delegation; an ambiguous conflict, uncertain ownership, missing review evidence or possible user-work loss stops for human input. Do not choose a convenient content value or guess at the user's intent.

Fetch immediately before normal push. Verify the approved parents, full tree bytes/modes, original commits as ancestors and complete outgoing range against the review manifest. If the remote advances again, stop that push and reconcile the new pinned state through the same gates; no blind repeated push or old-consensus reuse. A rejected push is not permission to force it.

The generic `tools/release-git-guard.mjs` deliberately remains read-only and rejects merges/divergence. Do not run its failing result and ignore it. The merge lane instead uses separately reviewed, action-specific native Git/index/tree/parent/range checks, as in010. Ordinary guarded releases resume once HEAD and fetched origin agree. Hash pins establish byte identity to reviewed inputs, not independent review or content truth.
